# Planner rules: the transparent recommender

Module `engine/app/planner_rules/` (`recommend`, `test_ids`, `calibrate`). Five rules on the hourly physics in `engine/app/hourly/`: yield from pvlib on PVGIS for this roof's orientation, the evening share from the BDEW H25 profile. Fit and score: `cd engine && uv run python -m app.planner_rules.calibrate`, which also rewrites the rules and constants below from the same `rules_table()` that `recommend()` returns, so the wording here and in the UI is identical.

## The data overruled the first rules
The brief's first PV rule (cover annual use times a ratio) scored PV 28% within tolerance on the test half; a base array plus a share of use scores 40%. Its first battery rule (store one evening's use) sized the battery right in 41%; kWh per kWp of array scores 48%. The experts fit a standard array first and size the battery to the array, not to the evening. One evening's use stays in each battery derivation as the physics check.

## Rules and constants

## Interface
`recommend(inputs, catalogue=None, overrides=None, roof=None, constants=None) -> {design, components, explanation, rules, version}`. `overrides`: a number fixes a size, null fixes none, "include" asks for it; the battery re-sizes around a fixed PV. `constants`: a `calibrate(fit_df)` result in place of `constants.json`.
